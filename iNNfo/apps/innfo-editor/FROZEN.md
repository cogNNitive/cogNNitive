# innfo-editor is FROZEN

Decision: 2026-10-14 (maintainer), OpenSpec change `2026-10-13-s5-retire-innfo-editor`,
phase S5-freeze (variant A3). This app is **not maintained**. It is kept in place so the
parity audit and ports for the domain console (S3a/S3b) can read it, and so the hosted app
keeps being served. Deleting it is a later, separate step (S5-delete).

## State

- The source is unchanged. It is **not** an npm workspace (`package.json` `workspaces` lists
  `iNNfo/packages/*` only), so `npm ci` does not install its dependencies.
- It is outside every gate: root `typecheck` / `test` / `test:coverage`, the pre-push hook,
  CI (`quality`, `site`), `scripts/build-docs.mjs`, `scripts/sync-versions.mjs`,
  `scripts/check-integrity.js`, `scripts/verify.js`, eslint, and the two source guards
  (`legacy-write-guard`, `nn-name-regex-guard`). `test/editor-freeze.test.mjs` keeps it that way.
- The hosted app at `https://cognnitive.com/innfo/app/` is a **committed static build** in
  `docs/innfo/app/` (`index.html`, `assets/`). The Pages publish replaces the whole tree, so
  removing that folder removes the live app. It was built from this source with
  `base=/innfo/app/` and is not rebuilt by CI.
- `jsdom` and `happy-dom` moved to the root `devDependencies`: gated console suites import
  them and only this app used to declare them.
- Last fully gated state: git tag `innfo-editor-frozen` (created by the maintainer at
  integration; see the change's `tasks.md`).

## What will rot

- `src/config/samples.ts` (`SHIPPED_BLUEPRINT_VERSIONS`) is no longer regenerated by
  `npm run sync:versions`. `tests/unit/shipped-template-versions.test.ts` would fail if run.
- It aliases `@cognnitive/innfo-core` to the core **source** (`../../packages/innfo-core/src/browser.ts`),
  so a core refactor can break `vue-tsc` and `vite build` here without anyone noticing.
- It does not understand newer L3 shapes (changesets, stable identity). Specs it fetches
  from `raw.githubusercontent.com` are write-once, so it keeps loading, only less well.
- Its 740 tests are the executable description of the behaviour S3a audits; they stopped running.

## How to thaw

1. Re-add `"iNNfo/apps/*"` to `workspaces` in the root `package.json`.
2. Re-add the editor to the root `typecheck`, `test` and `test:coverage` scripts
   (`&& npm --workspace=@cognnitive/innfo-editor <typecheck|test|run test:coverage>`).
3. `npm install` from a normal checkout (not a worktree junction), commit the lockfile.
4. Remove `'iNNfo/apps/innfo-editor/**'` from the ignores in `eslint.config.mjs`.
5. Run `npm --workspace=@cognnitive/innfo-editor run typecheck` and `... test`, fix what rotted
   (start with `samples.ts`: regenerate its version table by hand from the `spec_NN.md` files).
6. Restore the CI `quality` steps, the `check-integrity.js` Group 5 run, the
   `build-docs.mjs` build/stage step, and decide whether to re-add the scope of the two source guards.
   Update `test/editor-freeze.test.mjs` (or delete it).

To rebuild the hosted app: `npm --workspace=@cognnitive/innfo-editor run build`, then copy
`dist/` over `docs/innfo/app/` (keep `404.html` and `starter/`).

## End state

Deletion, once the console covers the audited behaviour and the maintainer signs off:
see S5-delete in the change's `tasks.md` (section B).
