## Requirements
### Requirement: The Registry Is Generated From Field Definitions

The skill MUST ship a generated registry (`lib/field-registry.generated.json`) built by one generator from the blueprint `spec_NN.md` Field Definitions and its frontmatter `validation.conditional_fields`, listing for every Field Definition its name, the Concepts where it is settable, type, options, blueprint default, and whether it participates in the cascade. The Field Definitions MUST NOT gain a consumer annotation. A generated human-readable reference (`parameters.md`) MUST be produced from the same data. The registry MUST be regenerated by one command and MUST NOT be edited by hand.

#### Scenario: Registry equals the blueprint

- GIVEN the blueprint `spec_NN.md`
- WHEN the registry is regenerated
- THEN it lists exactly the Field Definitions of the blueprint with their Concepts, types, options and defaults

#### Scenario: Cascade parameters are flagged

- GIVEN the Field Definition `transition` listing `Scene`, `Video` and `Series`
- WHEN the registry is read
- THEN `transition` is flagged as a cascade parameter with those Concepts

### Requirement: Registry Freshness Is A Gate

A `--check` mode MUST fail with a non-zero exit and name each stale artifact when the committed registry or `parameters.md` differs from what the blueprint generates. `node scripts/verify.js` MUST run it.

#### Scenario: Stale registry fails

- GIVEN a Field Definition changed without regenerating the registry
- WHEN the registry runs with `--check`
- THEN it exits non-zero and names the registry file

#### Scenario: Fresh registry passes

- GIVEN a regenerated registry
- WHEN `--check` runs
- THEN it exits zero

### Requirement: No Hand-Copied Parameter Lists

The engine's conditional-fields table, the preset parameter list, the cascade parameter list and the draft procedure's allowed keys MUST be read from the registry. No script MUST contain its own copy of a field list, and the drift tests that compared copies MUST be replaced by this single source.

#### Scenario: Preset parameters come from the registry

- GIVEN a Field Definition that lists `Preset` among its Concepts
- WHEN the engine validates a Preset
- THEN that parameter is accepted without an engine code change

#### Scenario: No private list remains

- GIVEN the skill's scripts
- WHEN they are searched for literal lists of field names equal to a registry subset
- THEN none is found

### Requirement: Unknown And Retired Keys Are Rejected

Every document read by a run (episode, Series scope, domaiNN defaults, proposed changeset) MUST be rejected before any spend when it carries a `::` key that the registry does not define for that Concept (`unknown-key`) or that is retired (`retired-key`). The error MUST name the document, the Concept, the key and, for retired keys, the replacement if one exists. No alias, translation or silent ignore MUST exist.

#### Scenario: Unknown key

- GIVEN a Scene declaring `scene_tts_model::`
- WHEN the pre-compile check runs
- THEN it fails with `unknown-key` naming the Scene and the key

#### Scenario: Retired key

- GIVEN a Video declaring `voice_tone::` or `scene_duration::`
- WHEN the check runs
- THEN it fails with `retired-key` and the run does not start

#### Scenario: Key valid on another Concept

- GIVEN a Scene declaring `avatar_resolution::`, which is defined only for `Layer`
- WHEN the check runs
- THEN `unknown-key` names the Scene and states the key is not defined for `Scene`

### Requirement: Every Field Is Read And Every Read Is Defined

Which module consumes each field MUST be declared in code (a field-to-module map). A test MUST fail when a registry field has no declared consumer (dead field) and when the map names a field absent from the registry (phantom field).

#### Scenario: Dead field detected

- GIVEN a Field Definition that no entry of the consumer map names
- WHEN the registry-usage test runs
- THEN it fails naming the field

#### Scenario: Phantom field detected

- GIVEN a consumer map entry naming a field that has no Field Definition
- WHEN the test runs
- THEN it fails naming the field and the module
