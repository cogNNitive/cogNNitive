# Specification: Workspace Hub Agent Prompt Generator

## Purpose

Defines the functional and technical requirements for the **"Regenerate All Consoles" Prompt Generator** embedded in `workspace_hub.html` and its compilation procedure `compile_workspace_hub_NN.md`.

## Requirements

### Requirement: Header Action Button
`workspace_hub.html` MUST provide a header action button labeled "Regenerate Consoles" with a refresh/sync icon, accessible and styled distinctly from search inputs. The same prompt-generation action MUST ALSO be reachable from the editor host (`ConsoleHubView.vue`) whenever the compiled hub artifact is absent, so the action exists before the artifact it acts upon. The artifact button and the host action MUST both open the same generated prompt for equivalent inputs.

#### Scenario: Button present inside the compiled artifact
- GIVEN a compiled `workspace_hub.html` opened via `file://`
- WHEN its header renders
- THEN the "Regenerate Consoles" button is present and opens the prompt modal

#### Scenario: Action reachable before the artifact exists
- GIVEN the editor Consoles view with no compiled hub artifact (`loadState === 'not_found'`)
- WHEN the Consoles view renders
- THEN a primary generation action is visible in the host header and the empty state
- AND activating it opens the agent prompt without requiring the artifact on disk

### Requirement: Prompt Generation Modal
- Clicking the action button MUST open an interactive modal (`#prompt-modal`).
- The modal MUST include:
  - Header with title ("Agent Instruction Generator") and close button (`ESC` key or click outside closes the modal).
  - Info notice explaining what the prompt does.
  - Readonly `<pre>` / `<code>` text area displaying the dynamically generated agent prompt.
  - Primary button **"Copy Prompt"** with clipboard integration (`navigator.clipboard.writeText` with fallback for restricted environments).
  - Confirmation visual indicator ("Copied!" state).

#### Scenario: Action button opens the prompt modal
- GIVEN a rendered workspace hub
- WHEN the "Regenerate Consoles" action button is activated
- THEN the `#prompt-modal` modal opens with the generated prompt displayed
- AND it closes via the close button, `ESC`, or an outside click

#### Scenario: Copy Prompt uses clipboard with fallback
- GIVEN an open prompt modal
- WHEN the "Copy Prompt" button is activated
- THEN the prompt text is written to the clipboard via `navigator.clipboard.writeText`
- AND a "Copied!" confirmation is shown, with a fallback when clipboard access is restricted

### Requirement: Dynamic Prompt Content Contract
The generated prompt MUST dynamically incorporate the workspace metadata (title, version), the list of models, the template-specific procedure mapping, and step-by-step agent instructions covering model validation, sequential console regeneration in `artifacts/`, and Workspace Hub compilation. The model list MUST come from `#innfo-workspace-data` inside the artifact and from the editor's discovered models when generated by the host. The mapping MUST reference paths that exist in the current repository layout: since the blueprint migration moved `iNNfo/specs/templates/` to `iNNfo/specs/bluepriNNts/`, every mapped procedure path and the hub-compilation step MUST use the `bluepriNNts` root, and no generated prompt MAY reference a non-existent `specs/templates/` path.

#### Scenario: Emitted procedure paths exist
- GIVEN the generated agent prompt for any workspace
- WHEN its procedure paths are extracted
- THEN every path uses the `bluepriNNts` root
- AND no emitted path contains `specs/templates/`

#### Scenario: Editor and artifact agree on the prompt
- GIVEN the same workspace metadata and model list
- WHEN the editor host and the artifact each generate a prompt
- THEN both emit the same procedure mapping for the same template

#### Scenario: Editor uses discovered models, not the static slot
- GIVEN the editor with a loaded workspace whose domain models are discovered in the store
- WHEN the host action generates a prompt
- THEN the model list comes from the discovered models
- AND the prompt does not depend on the artifact's `#innfo-workspace-data` slot being present

### Requirement: Offline & file:// Hygiene
- The modal, script, and prompt generation MUST function 100% offline via `file://`.
- Banned: `fetch()`, `XMLHttpRequest`, ES Modules (`type="module"`), external unbundled scripts.

#### Scenario: Hub functions offline via file://
- GIVEN a compiled `workspace_hub.html` opened directly via `file://`
- WHEN the prompt modal is opened and the prompt is generated
- THEN no `fetch()`, `XMLHttpRequest`, ES Module, or external unbundled script is used
- AND the flow completes with no network access
