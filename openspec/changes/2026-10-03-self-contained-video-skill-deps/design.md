# Design: Self-Contained Video Skill Dependencies

## Technical Approach

Make `nn-video-script` runnable from an installed copy: vendor the parser as a committed ESM bundle (clone of the trannsform-core-mirror pattern), point both importers at it by relative path, author the missing Remotion entry/composition, install the renderer on demand behind consent, and make Remotion the only renderer. `manifest/source.yaml` is untouched.

## Architecture Decisions

| Decision | Option A (chosen) | Option B rejected | Rationale |
|---|---|---|---|
| Parser delivery | Commit ESM mirror `scripts/lib/innfo-video-parser.generated.mjs`, generated by `scripts/build-video-parser-mirror.mjs` | Publish npm package / keep `tsx` | No registry, no `node_modules`, no TS loader; matches proven trannsform-core-mirror. |
| Mirror format | `format:'esm'`, `bundle:true`, `platform:'node'`, `target:'node20'`, `preserveSymlinks:true`, banner, `\r\n→\n`, `...node_modules/` normalize | `cjs` | Consumers are ESM (`import { parse }`); `preserveSymlinks` prevents worktree junction drift (per `build-console-payload.mjs`). |
| **VUS spec JSON** | Embed via `loader:{'.json':'json'}` + `define`, replacing `loadVusSpec()`'s on-disk `packageRoot()` read | Ship a sibling `specs/V_0-3-3.json` | `index.ts` reads `specs/V_0-3-3.json` from disk at module load; a bare mirror would throw `ENOENT`. Bundling the parsed JSON is the only self-contained option. Generate-time hash is embedded. |
| drift check | Append `--check` step to `scripts/verify.js` | None | Spec scenario requires verify to fail on stale mirror. |
| Parser import seam | Relative `./lib/innfo-video-parser.generated.mjs` in compiler + runner | Package import | Removes `@cognnitive/...` and `../../../iNNfo/...`. |
| Child-process boundary | **Keep** `vus-parse-runner.mjs` as a child (drop `--import tsx/esm` only) | Inline into `vus-parse.mjs` | Runner isolates parser `console.log` diagnostics from the JSON stdout contract; inlining would mix streams. tsx was the only reason for the loader flag. |
| Render API | `selectComposition({serveUrl,id,inputProps})` → `renderMedia({composition,serveUrl,...})` | Hand-built composition object | **Bug**: current `tryRemotionRender` fabricates `{id,fps,durationInFrames,...}` and passes it as `composition`; `renderMedia` expects the resolved composition from `selectComposition`. The hand-built shape is not the official contract and is unvalidated. |
| Fallback policy | Delete FFmpeg-from-PATH + silent mock; throw named non-zero error (`VideoRenderError`) | Keep silent fallback | Spec: mock MUST NOT masquerade as a render. |
| Mock | Behind explicit `--allow-mock` flag only | Always | Preserves CI. |
| Audio duration | `@remotion/media-parser` `parseMedia({src,fields:{durationInSeconds:true}})` | ffprobe/ffmpeg/size-estimate | Spec: duration without FFmpeg-from-PATH. |
| OS TTS fallback | Delete `_synthesizeWindowsSapi` + both call sites | Keep behind flag | Spec: no OS-native TTS remaining. |
| Provider deps | Declare in `SKILL.md` frontmatter `depends_on` | Prose | Matches `nn-trannsform` shape. |
| Engine install | New `ensure-engine.mjs`, idempotent, consent-gated | Auto-install on render | Spec: consent + size notice before proceed; re-run is no-op. |

## Interfaces / Contracts

**Mirror export** — same named surface as `index.ts`: `parse(text,title?) → { project, issues }`, `validate`, `VUS_SPEC {version,sha256,spec}`, `ScriptParser`, domain types. Consumers only use `parse`.

**ensure-engine CLI**
```js
// node ensure-engine.mjs [--check] [--yes]
// exit 0 = ready; exit 1 = missing/declined
// idempotency: import '@remotion/renderer' resolves AND cached version matches SKILL pin → print "engine present", no install
// notice (before any install): approx total MB, then "headless browser downloads on first render"
// provider: reports missing WAVESPEED_API_KEY/REPLICATE_API_TOKEN or optional MCP, requests consent
```

**Composition input contract** — `remotion-entry.tsx` registers `ScriptRoot`; `ScriptRoot` reads `inputProps = RemotionCompositionManifest` unchanged. `id = manifest.compositionId`, `fps/width/height/totalDurationInFrames` from manifest. `selectComposition({serveUrl, id: manifest.compositionId, inputProps: manifest})` must match the registered `id` — mismatch is the loud error.

## Testing Strategy

| Layer | What | Approach |
|---|---|---|
| Unit | Mirror parse of a valid script; stale mirror fails `--check` | Node test importing generated `.mjs`; run builder `--check` after editing source. |
| Unit | `ensure-engine` idempotent no-op; consent decline exits 1 | Inject `loadModule`/fs fakes (existing `deps` seam in `tryRemotionRender`). |
| Integration | `renderVideo` calls `selectComposition` then `renderMedia`; missing module → named error; `--allow-mock` writes mock | Fake `@remotion/renderer`/`@remotion/bundler` via `loadModule`; assert call order + no FFmpeg spawn. |
| Integration | `vus-parse.mjs` child spawn has no `tsx` arg | Inspect `spawnSync` args / run on fixture. |
| Regression | SAPI absent from source; manifest shape unchanged | grep assertion + existing `video-engine-cli.test.mjs` pass. |

## Migration / Rollout

No data migration. One commit: mirror + builder + verify step, then import rewires, then entry/composition, then engine/install/render, then SAPI removal + SKILL. Existing tests keep passing; CI uses `--allow-mock`. Rollback = revert commits (mirror + verify step vanish; imports restore).

## Resolved Questions

- [x] **Mirror spec embedding mechanism**: RESOLVED — embed `V_0-3-3.json` in the mirror via esbuild `loader:{'.json':'json'}` and stub `packageRoot()`/`loadVusSpec()`. Single self-contained artifact; the drift-guard covers the embedded spec too. (Rejected: sibling `specs/` file — `packageRoot()` walks up for a `package.json` and is unpredictable in an installed copy; rejected: changing parser `src` to module-import the JSON — out of the skill's scope.)
- [x] Composition `durationInFrames` source: RESOLVED — fixed from `manifest.totalDurationInFrames` (the compiler already computes it at `remotion-scene-compiler.mjs:661`). `calculateMetadata` not needed for the structural composition.
- [x] `ensure-engine` version pin location: RESOLVED — SKILL.md frontmatter, alongside the existing `vus_spec: {version, sha256}` pin. No new `engine-pin.json` file (none exists in the repo).
- [x] `nn-trannsform`-style `bundled_blueprints`/install metadata in frontmatter: RESOLVED — NOT applicable; that block exists because `nn-trannsform` vendors blueprints, which `nn-video-script` does not.
