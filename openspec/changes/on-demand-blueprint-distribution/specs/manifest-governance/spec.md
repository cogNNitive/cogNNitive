# Delta Spec: manifest-governance

## ADDED Requirements

### Requirement: Core-Only Blueprint Inventory in Source Manifest

`manifest/source.yaml` and `scripts/generate-canonical-registry.mjs` (`canonical-registry.ts` in `@cognnitive/innfo-core`) MUST restrict bundled `bluepriNNts` inventory to the 7 Core `bluepriNNts` (`domaiNN`, `changes`, `sidecar`, `sources`, `artifacts`, `procedures`, `blank`). Optional domain and vertical `bluepriNNts` MUST be governed through `iNNfo/specs/bluepriNNts/catalog.json` (`scripts/blueprint-catalog.mjs`) including `tier`, `access`, `embedded_skills`, and release pins.

#### Scenario: Validating core-only manifest and canonical registry inventory
- **GIVEN** `manifest/source.yaml` and `canonical-registry.ts` generated by `scripts/generate-canonical-registry.mjs`
- **WHEN** `scripts/verify.js` validates the blueprint inventory
- **THEN** all 7 Core `bluepriNNts` (`domaiNN`, `changes`, `sidecar`, `sources`, `artifacts`, `procedures`, `blank`) are present in `manifest/source.yaml` and `canonical-registry.ts`
- **AND** optional vertical `bluepriNNts` are absent from `manifest/source.yaml` and validated against `catalog.json` instead

---

### Requirement: Memoized Remote Commit Verification

`scripts/manifest/lib/manifest-rules.js` MUST memoize GitHub API commit verification requests by `(repo, ref, commit)` in memory so that shared release commits across manifest entries are queried at most once per validation run.

#### Scenario: Repeated commit tuples trigger a single GitHub API lookup
- **GIVEN** a manifest containing multiple skills and blueprints sharing the same `(repo, ref, commit)` tuple
- **WHEN** `manifest-rules.js` verifies remote commit existence during release or manifest validation
- **THEN** only one GitHub API request is issued per unique `(repo, ref, commit)` tuple
- **AND** total GitHub API calls per release verification remain `<= 45`
