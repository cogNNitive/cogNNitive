# Proposal: Console design tokens and UI kit

## Why

Consoles look and behave differently for the same concepts, and the review UX (change 4) has no shared building blocks. Verified 2026-09-30:

| Gap | Evidence |
|---|---|
| Two card/pill implementations | `InnfoConsole` (`console/innfo-runtime.js:784/804/910`, `innfo-concept-pill`) vs `InnfoModelViewer` (`render-model-viewer.js:296-301`, `.chip`/`.el-head`/`.el-name`). The canonical `model_console.html` uses the latter, contradicting `console-architecture` ("L1 primitives in innfo-runtime, composed by all consoles"). |
| No shared tokens | Every shell redefines `:root` (`--bg` is `#ffffff`, `#f9fafb`, `#f8fafc`; dark `#0a0a0a`/`#0f172a`/`#090d16`/`#09090b`); dark mode only via `prefers-color-scheme`; component CSS lives in shells (`artifact_shell.html:503`). |
| Unguarded build | `innfo-console.bundle.js` is a concatenation generated by `scripts/build-console-bundle.mjs` (uPlot, visuals, innfo-runtime, model-viewer, stepper), not wired to any npm script, with no source-vs-bundle drift check. |

## What Changes

- **Tokens**: bundle injects one `<style>` of semantic tokens (`--innfo-surface`, `--innfo-text`, `--innfo-accent`, `--innfo-concept-1..n`, status `pending|applied|rejected|stale`), light + dark, `data-theme` override. Shells keep layout CSS only.
- **`InnfoUI`**: new UMD source `console/ui-kit.js`, pure `(data, opts) -> HTMLElement`, no shadow DOM, `data-*` hooks. First `ConceptPill`, `ElementCard`, `MarkerChip`, `StatusBadge`; then `CitationIcon`, `FieldRow`.
- `InnfoConsole` and `InnfoModelViewer` consume `InnfoUI`; `renderConceptPill`/`renderElementPill`/`renderCards` internals and `.chip`/`.el-head` builders are deleted (no aliases).
- Build: `ui-kit.js` added to `SOURCES`; npm script + drift test (bundle == build output); build process documented.
- Kitchen-sink fixture HTML (every component, light/dark) + one DOM test per component (Vitest pragma; happy-dom is the existing console-test env, jsdom where `happy-dom` diverges).
- Documented contract so blueprint/user-generated consoles reuse tokens + components.

## Capabilities

### New Capabilities
- `console-ui-kit`: token set, theming rules, `InnfoUI` component contract, offline/UMD constraints.

### Modified Capabilities
- `console-architecture`: L1 primitives move from `innfo-runtime` to `InnfoUI`; every renderer MUST compose them.
- `innfo-console-runtime`: bundle composition includes `ui-kit.js`; bundle MUST match its sources.

## Chain, release, rename

- **Position**: 2 of 1->2->3->4. Depends on change 1 (shell collapse, needs lint) so tokens migrate fewer shells. Change 3 reuses `StatusBadge`; change 4 builds on all components.
- **Release**: new `innfo-console-v0.7.0` (current `0.6.0`, `manifest/source.yaml:196`), regenerated bundle, new CDN file; refs via `channel-refs.js`/`sync-versions.mjs`, never hand-edited. Shell edits under `bluepriNNts/**` need a `templates-v*` tag + repin in the same batch.
- **Left to the rename change**: legacy `templates/console` URLs, pins, `$id`s, and the "Level 1/2/3 console" tier wording in `console-architecture`.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Visual regressions in specialized layouts (`timeline`, `procedure_console`) | Med | Kitchen-sink + per-shell token mapping; migrate last |
| Vendored stale bundle copies (`metrics/samples`, `procedures/samples`) | Med | Regenerate or declare frozen in design |
| Diff far above 400 lines (generated bundle doubles source diff) | High | Chained PRs, see below |

## Size (ask-on-risk)

Estimate ~1,400-1,900 changed lines including the regenerated bundle. **Exceeds 400.** Proposed slices: (a) tokens + build drift guard, (b) `InnfoUI` first 4 + tests + fixture, (c) migrate both renderers + delete duplicates, (d) shells + `CitationIcon`/`FieldRow`, (e) release.

## Rollback

Revert the slice commits on `dev`; the stable channel keeps `innfo-console-v0.6.0` until the new tag is repinned. Published tags are never deleted.

## Success Criteria

- [ ] One implementation per primitive; `rg "renderConceptPill|className = 'chip'"` finds none outside `ui-kit.js`.
- [ ] No shell defines color tokens; `data-theme="dark"` works without OS preference.
- [ ] Drift test fails when a source changes without rebuilding.
- [ ] Bundle still has no `fetch(`/`type=module`; offline double-click works.
