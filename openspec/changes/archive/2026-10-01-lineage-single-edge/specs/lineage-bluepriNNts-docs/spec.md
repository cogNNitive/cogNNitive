# Lineage bluepriNNts and Docs (Delta, new capability)

## ADDED Requirements

### Requirement: cogNNitive bluepriNNt matches the projection output

`iNNfo/specs/bluepriNNts/cogNNitive/spec_NN.md` MUST declare exactly the fields the lineage projection writes, with `derived_from` typed `citation`:
- Sources: `raw_filename, media_filename, raw_hash, size, source_format, normalized_at, normalized_by, normalized_content, curated_csv, status, version, archive_path, superseded_by, derived_from`
- ModelRecords: `model_ref, knowledge_version, model_template, derived_from`
- Artifacts: `artifact_ref, artifact_format, derived_from`

Fields no code writes MUST be DELETED, not retyped: `generated_by`, `produced_by`, `derived_from_inputs`, `location`, `artifact_version`, `artifact_hash`, `model_version`, `raw_file`, and the `Artifact-Source Lineage` matrix. The stale section claiming cross-model qualified references are not validated MUST be removed (they are validated, `validator/workspaceReferences.ts`), and the `#slug` example MUST become `@` grammar. `template_version` MUST be bumped (edited in place; `spec_version` unchanged). The bluepriNNt is in `frozen_blueprints`, so it is not in `SHIPPED_BLUEPRINT_VERSIONS`.

#### Scenario: Declared fields equal written fields
- GIVEN the bumped cogNNitive bluepriNNt and a record rendered by `renderLineageSections`
- WHEN declared view fields are compared with rendered fields per section
- THEN the sets are equal, and `derived_from` has type `citation`

#### Scenario: Dead fields are gone
- GIVEN the bumped cogNNitive bluepriNNt
- WHEN searched for `derived_from_inputs`, `generated_by`, `produced_by`, and `artifact_hash`
- THEN none is declared

#### Scenario: Sample record validates clean
- GIVEN a sample workspace record generated by the projection
- WHEN the cogNNitive validator runs
- THEN no dangling-reference diagnostics are reported for `derived_from`

### Requirement: domaiNN drops `kNNowledge.derived_from`

`iNNfo/specs/bluepriNNts/domaiNN/spec_NN.md` MUST NOT declare `kNNowledge.derived_from`, since body `sources::` carries the relationship. Its version key is `blueprint_version` (not `template_version`) and MUST be bumped. Registration in `SHIPPED_BLUEPRINT_VERSIONS` MUST be produced by `npm run sync:versions` (generated `config/samples.ts`, gated by `sync-versions --check`), never hand-edited. The manifest `version:` (spec_version) is unchanged.

#### Scenario: Field absent
- GIVEN the bumped domaiNN bluepriNNt
- WHEN the `kNNowledge` concept fields are listed
- THEN `derived_from` is not among them

#### Scenario: Registration is generated
- GIVEN the bumped `blueprint_version`
- WHEN `npm run sync:versions` runs and then `sync-versions --check`
- THEN the check passes and `SHIPPED_BLUEPRINT_VERSIONS` contains the new version

### Requirement: Artifacts catalog bluepriNNt is kept as a discovery index

The artifacts catalog bluepriNNt (`iNNfo/specs/bluepriNNts/artifacts/`) MUST remain (it is a shipped `blueprints:` entry used by workspaces and pinned `parent_spec` URLs). Its `sources` and `produced_by` fields MUST be dropped because they duplicate the single edge, and its `blueprint_version` MUST be bumped. After this change exactly one PROV vocabulary exists (the cogNNitive record).

#### Scenario: Duplicating fields dropped
- GIVEN the bumped artifacts catalog bluepriNNt
- WHEN its fields are listed
- THEN neither `sources` nor `produced_by` is declared

#### Scenario: Catalog still discoverable
- GIVEN `manifest/source.yaml` and the canonical registry
- WHEN `node scripts/verify.js` runs
- THEN the artifacts catalog is still listed and generated registry and catalog files are in sync

#### Scenario: Single vocabulary
- GIVEN the repository after this change
- WHEN bluepriNNts declaring `produced_by` or PROV-like lineage fields are enumerated
- THEN none is found outside the cogNNitive record's `derived_from`

### Requirement: Documentation describes the shipped system

`docs/innfo/documentation/sources-citations-lineage.md` and `docs/skills/documentation/skills/citation-traceability.md` MUST be rewritten to cover: the `@` grammar, the three rules, record = view + journal, and the staleness principle. They MUST NOT contain OKF, "canonical view", or `sources/original/` references, and MUST use `@` (not `#slug`) in examples. Spec URL slugs MUST satisfy `check:spec-urls`.

#### Scenario: Forbidden terms absent
- GIVEN the two rewritten pages
- WHEN scanned for `OKF`, `canonical view`, `sources/original/`, and `#slug`-style example citations
- THEN none are found

#### Scenario: Required topics present
- GIVEN the two rewritten pages
- WHEN read
- THEN together they define the `@` grammar, the three rules, record as view plus journal, and the staleness principle

### Requirement: Scope boundaries

Published `_V_x-y-z_` spec files and frozen samples MUST NOT be edited. `ModelRecords` / `model_ref` vocabulary MUST NOT be renamed. No `templates-v*` tag, repin, or version bump of skills/MCP is part of this change.

#### Scenario: Frozen files untouched
- GIVEN the change diff
- WHEN checked against published `_V_x-y-z_` files
- THEN none are modified
