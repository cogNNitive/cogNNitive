# Proposal: Lineage as a Single Citation Edge

Input: `exploration.md` in this change folder (decisions approved by the maintainer on 2026-10-01). This proposal does not re-open those decisions; it scopes, sequences, and bounds them.

## Why

Lineage in a cogNNitive workspace is currently expressed several different ways that don't agree with each other. One relationship ("X was derived from Y") is stored, scraped, or inferred through at least five mechanisms:

| # | Mechanism | Where | Problem |
|---|---|---|---|
| 1 | kNNowledge body `sources::` citation | innfo-core `citation` field, validated by `validateWorkspaceSources` | The only edge innfo-core actually validates. This is the one to keep. |
| 2 | Artifact frontmatter `sources:` | regex-scraped by `parseFrontmatterSources` (`skills/nn-trannsform/scripts/lib/provenance-knowledge.js:406`) | innfo-core never validates it. |
| 3 | Artifact `model` / `model_name` + `knowledge_version` fallback | `provenance-knowledge.js:498-503` | An inferred edge with no citation grammar. |
| 4 | Console `export-meta` | read by `parseArtifactMeta` (`provenance-knowledge.js:437`) | Nothing emits it, so every console ends up with an empty `derived_from`. |
| 5 | Record view fields `derived_from`, `derived_from_inputs`, `generated_by` | cogNNitive bluepriNNt (`iNNfo/specs/bluepriNNts/cogNNitive/spec_NN.md:120`, `:155`) | Typed `reference` but filled with citations, so the validator reports dangling references that are false positives. |

On top of that there are duplicate resolvers and parsers (MCP vs core source resolver, editor `parseForPill`, console runtime `slugify`, `impact-checker.js` heading drift). There is also a self-verifying checker: `lineage-check.js` re-checks output it just generated, and its citation check strips only `#.*` (`skills/nn-trannsform/scripts/lib/lineage-check.js:81`). That produces false "does not resolve" errors on canonical `@` and CSV citations. Two PROV vocabularies exist side by side (cogNNitive vs the artifacts catalog bluepriNNt, and no script generates the catalog). User-facing docs contradict the code: they describe the `#slug` grammar, OKF, and `sources/original/`.

Why now: innfo-core already says "write sources::; lineage is computed" (`iNNfo/packages/innfo-core/src/validator/workspaceSources.ts:160`), and every consumer (editor, consoles, MCP) already sits on innfo-core. The remaining mechanisms are drift that has to be maintained, and fixes keep landing in only one place.

## Intent

ONE edge primitive: a `sources` citation (innfo-core `citation` field type; grammar `path@## Heading&subunit`, CSV `data.csv@RowID&col`). Each derived file writes it once, inside itself. Node roles (Source / kNNowledge / artifact) come from contract plus folder, not from stored types. `parent_spec` is conformance, not lineage, and stays untouched.

### Three rules

1. **What is cited is a Source.** Every Source has a normalized `.md` under `sources/nn/` that acts as the sidecar for the raw file (`source_file`, `sha256`, `size_bytes`, `normalized_at`). A curated CSV without a profile `.md` also gets a sidecar. Today it is registered with null metadata (`provenance-knowledge.js:173-190`).
2. **What derives cites its origin once, inside itself:**
   - kNNowledge: body `sources::`.
   - Markdown artifact: frontmatter `sources:`.
   - Console HTML: `innfo-model.meta.sources` (the `export-meta` convention is deleted).
   - CSV / JSON artifact: a `sources` column / field per row or record.
3. **An artifact reused as input is promoted to a Source** (`sources/export/`) and gets a sidecar. A terminal artifact either carries traceability as content or has none. The Procedures journal gives coarse run-level lineage.

**Staleness principle** (documented only, no new mechanism): file-level hops are checked by hash (raw -> sidecar `sha256`; kNNowledge -> console `sha256` + `export-console --stale`). Unit-level hops are checked by anchor resolution (heading / row).

### Lineage record: Option B (approved)

- The cogNNitive lineage record file stays.
- Its view sections (`# NN Sources`, `# NN ModelRecords`, `# NN Artifacts`) are regenerated by ONE innfo-core projection over the parsed workspace. nn-trannsform consumes it through an esbuild mirror, using the same pattern as `scripts/build-console-payload.mjs` -> `iNNfo/specs/bluepriNNts/console/console-payload.generated.cjs`.
- `# NN Procedures` stays an append-only journal. Hand-authored blocks pass through unchanged (e.g. `## NN External Watch Roots`, read by `skills/nn-trannsform/scripts/lib/external-scanner.js:108`).
- View fields in the cogNNitive bluepriNNt change type from `reference` to `citation`.

## Product Outcome

- A user (or agent) who wants to know "where did this come from?" gets the same answer from the editor Lineage tab, the console citation popover, MCP `resolve_sources`, and the lineage record. All four go through one resolver.
- Canonical `@` and CSV citations no longer raise false errors in `lineage-check.js` or the cogNNitive validator.
- Consoles show real upstream lineage instead of an empty `derived_from`.
- The editor groups `export/` correctly and its Lineage UI is in English.
- The docs describe the system that actually ships.

## Scope

### In scope

**Core (innfo-core)**
- One exported `parseCitation` (replaces the `parseKnowledgeUnitRef ?? parseSourceRef` pair used by consumers).
- One filesystem source resolver. `innfo-mcp/src/tools/validate.ts:293` `createWorkspaceSourceResolver` is removed in favor of `console/fs-source-resolver.ts` `createFsSourceResolver`.
- A lineage projection function (parsed workspace -> record view sections).
- `resolveUnitPath` accepts `kNNowledge/` only (drop `models/`).
- `#slug` remains a legacy READ path inside innfo-core only, with a warning (write-once specs and samples still use it). It is never written. A one-shot migration script rewrites non-frozen content.
- Validation of artifact frontmatter `sources:` and console `innfo-model.meta.sources` through `validateWorkspaceSources`.

**nn-trannsform (actioNN skill)**
- Delete the scrapers in `provenance-knowledge.js`: `scrapeSourceRefs`, `parseFrontmatterSources`, `parseArtifactMeta`, `collectSources`, `collectArchivedSources`, `collectModels`, `collectArtifacts`. Replace them with the mirrored core projection.
- Delete the `model` / `knowledge_version` fallback (`:498-503`) and the deprecated `artifacts/` folder fallback (`:481-490`). The second one is not listed in exploration.md, but it is the same kind of alias and the maintainer has said no backwards compatibility.
- `lineage-check.js`: drop the checks that re-verify freshly generated output and delegate citation checks to innfo-core (this removes the `:81` bug and the `models/` skip at `:82`).
- `impact-checker.js`: delegate heading-drift and CSV-row / subunit checks to innfo-core.
- Sidecar generation for curated CSVs.
- Drop the stored `is_synthetic` field. It is derivable from the `source_file` prefix `sources/export/`, and author comes from the Agent Modification block / `source_type: feedback` (confirm the feedback-docs case at `skills/nn-trannsform/scripts/lib/scanner-core.js:661`).
- Promotion of reused artifacts into `sources/export/` with a sidecar.

**Consoles**
- `compile_model_console` / the console procedure emits `innfo-model.meta.sources`.
- Delete the `export-meta` convention.
- Console runtime `slugify` (`iNNfo/specs/bluepriNNts/console/innfo-runtime.js:33`) is aligned with core (shared via the existing payload mirror).
- The contract example handles `@` citations.

**Editor (`iNNfo/apps/innfo-editor`)**
- `utils/sourceRef.ts` `parseForPill` -> core `parseCitation`. Fix the stale header comment (`:8-13`).
- `stores/knowledgeStore.ts:217` `getSourceCitations`: replace the case-insensitive basename-suffix match with the core resolver.
- `utils/explorerClassify.ts:20`: `artifacts/` -> `export/`, no fallback (used by `FileTreeNode.vue:125`, `WorkspaceExplorer.vue:228`).
- Translate the Spanish UI strings in `components/editor/FilePreviewModal.vue` ("Archivo Original", "Linaje", "normalizado", "cita", ...) to English.
- The pill and modal handle `@` citations.

**bluepriNNts and docs**
- cogNNitive bluepriNNt (`iNNfo/specs/bluepriNNts/cogNNitive/spec_NN.md`): view fields become `citation`. Remove the stale cross-model claim at `:245` (`validator/workspaceReferences.ts:397` does validate qualified refs). Bump `template_version`.
- Artifacts catalog bluepriNNt (`iNNfo/specs/bluepriNNts/artifacts/`): merge into cogNNitive or delete (decision for design).
- domaiNN bluepriNNt: drop `kNNowledge.derived_from` (`iNNfo/specs/bluepriNNts/domaiNN/spec_NN.md:94`), which duplicates body `sources::`. Bump `template_version`.
- Register the bumped versions in the editor's `SHIPPED_TEMPLATE_VERSIONS`.
- Rewrite `docs/innfo/documentation/sources-citations-lineage.md` and `docs/skills/documentation/skills/citation-traceability.md` to cover: `@` grammar, the three rules, record = view + journal, and the staleness principle. Remove the OKF, "canonical view", and `sources/original/` contradictions.

### Out of scope (non-goals)

- Renaming canonical vocabulary. `ModelRecords` and `model_ref` predate the kNNowledge rename and are flagged as a follow-up, not touched here.
- Releasing: `templates-v*` tag, `manifest/source.yaml` repin, skills/MCP version bumps.
- Editing published `_V_x-y-z_` spec files or frozen samples (their `#slug` usage stays readable through the core legacy path).
- `parent_spec` / conformance semantics.
- New staleness machinery beyond the existing hashes and anchor resolution.
- Editor graph changes (it already drops `origin: 'source'` edges, `composables/useGraphData.ts:109`).
- A validator for CSV row-unit `@` citations beyond what core already provides, unless it falls out of the delegation for free.

## Approach

Deletion first, then the minimum replacement:

1. Add the core primitive (`parseCitation`, one resolver, projection) with tests, and mirror it to nn-trannsform with esbuild exactly as the console payload is mirrored. No new build pattern.
2. Switch nn-trannsform to the mirror and delete the scrapers and fallbacks in the same slice, so no parallel path exists at any point.
3. Make every producer emit `sources` (consoles, procedures, CSV/JSON artifacts). Then the last inferred edge (the `model` fallback) can go without leaving artifacts lineage-less.
4. Point the editor and MCP at the core functions and delete their local copies.
5. Update bluepriNNts and docs to describe what now exists.

Anything that has to survive temporarily (for example the `#slug` legacy read) carries a `legacy:lineage-single-edge/<id>` marker plus a `legacy-ledger.yaml` entry with a removal condition.

## Affected Modules

- **iNNfo / innfo-core**: new public exports (`parseCitation`, resolver, projection). Relative imports need `.js` (NodeNext).
- **iNNfo / innfo-mcp**: loses its private resolver. `resolve_sources` behavior is unchanged.
- **iNNfo / innfo-editor**: Lineage tab, explorer classification, UI strings.
- **actioNN / nn-trannsform**: lineage record generation, checks, sidecars. It ships its own `package.json`, so CI needs `npm ci --prefix`.
- **iNNfo / specs / bluepriNNts**: cogNNitive, domaiNN, artifacts, console.
- **docs**: lineage and citation pages.

## Risks

- **Mirror drift / worktree path drift**: esbuild mirrors have shown junction-path drift in worktrees (see the decoupled-release-pipeline proposal). The new mirror inherits that risk, so the generator must normalize paths the same way the console payload one does.
- **Template version registration gap**: bumping two or three bluepriNNts without registering them in `SHIPPED_TEMPLATE_VERSIONS` has recurred repeatedly. On merge to main without a new `templates-v*` tag, verify goes red (release constraint).
- **Deleting the `model` fallback too early** leaves existing artifacts with empty lineage. Slice 3 must land producers before the deletion.
- **Projection output diff**: regenerated view sections will differ from today's scraped output (citations instead of names, consoles now populated). Existing workspaces get a one-time noisy diff in the record.
- **Editor resolver strictness**: replacing the fuzzy suffix match can make previously "resolved" (actually ambiguous) citations show as unresolved. That is correct, but visible.
- **`is_synthetic` removal**: depends on confirming the feedback-docs case at `scanner-core.js:661`.

## Rollback

Each slice is a self-contained commit range on `dev` and reverts cleanly (`git revert`). Slice 2 is the only one that removes behavior without core fallback, but the record file is regenerable: reverting slice 2 and rerunning the old generator restores the previous view sections. The Procedures journal is append-only and is never rewritten by this change, so no journal data is at risk. bluepriNNt changes are not released until a `templates-v*` tag is cut, so reverting before release has no user-facing effect.

## Success Criteria

- `provenance-knowledge.js` contains no scrapers. Record view sections come from the core projection via the mirror.
- One citation parser and one filesystem resolver exist in the repo. `rg` finds no `createWorkspaceSourceResolver`, `parseForPill`, or second `slugify` implementation outside core.
- `lineage-check.js` reports no errors for canonical `@` and CSV citations on the sample workspaces.
- The cogNNitive validator reports no dangling-reference false positives on `ModelRecords.derived_from`.
- Every console in a sample workspace has non-empty upstream lineage from `innfo-model.meta.sources`.
- No code reads `export-meta`, `is_synthetic`, an `artifacts/` folder fallback, or the `model` / `knowledge_version` fallback.
- The editor shows `export/` items as artifacts and contains no Spanish UI strings in `FilePreviewModal.vue`.
- The docs describe the `@` grammar and the three rules with no OKF / `sources/original/` references.
- `node scripts/verify.js`, `npm run check:integrity`, and the legacy-ledger guard pass.
