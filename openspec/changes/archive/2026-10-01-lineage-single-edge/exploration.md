# Exploration: lineage-single-edge

Decided with the maintainer on 2026-10-01. Based on read-only investigations of the nn-trannsform lineage pipeline, innfo-core, the spec layer, and every consumer (editor, consoles, MCP).

## Goal

Unify lineage/traceability to ONE edge primitive: a `sources` citation (innfo-core `citation` field type, canonical grammar `path@## Heading&subunit`, CSV `data.csv@RowID&col`), written ONCE in the deriving file. Node roles (source / kNNowledge / artifact) come from contract + folder, not from stored types. `parent_spec` is conformance, NOT lineage, and is untouched.

## Three rules (agreed)

1. **What is cited is a Source.** Every Source has its normalized `.md` in `sources/nn/` acting as sidecar for the raw file (origin metadata: `source_file`, `sha256`, `size_bytes`, `normalized_at`). A curated CSV without a profile `.md` must get a sidecar too (`skills/nn-trannsform/scripts/lib/provenance-knowledge.js:173-190` is the weak case today, registered with null metadata).
2. **What derives cites its origin once, inside itself:**
   - kNNowledge: body `sources::` field.
   - Markdown artifact: frontmatter `sources:`.
   - Console HTML: `innfo-model.meta.sources` (NOT `export-meta`; nobody emits `export-meta`, delete that convention).
   - CSV / JSON artifact: a `sources` column / field per row / record.
3. **An artifact reused as input is promoted to a Source** (`sources/export/`, already exists) and gets a sidecar. A terminal artifact carries traceability as content (the procedure includes it) or has none; the Procedures journal gives coarse run-level lineage.

**Staleness principle** (document it, add nothing): file-level hops use a hash (raw -> sidecar `sha256`; kNNowledge -> console `sha256` + `export-console --stale`); unit-level hops use anchor resolution (heading / row).

## Lineage record decision: OPTION B (maintainer approved)

- Keep the cogNNitive lineage record file.
- View sections (`# NN Sources`, `# NN ModelRecords`, `# NN Artifacts`) are regenerated by ONE projection function in innfo-core over the parsed workspace, consumed by nn-trannsform via the esbuild mirror pattern (like `scripts/build-console-payload.mjs` -> `iNNfo/specs/bluepriNNts/console/console-payload.generated.cjs`).
- Delete all JS scrapers in `provenance-knowledge.js` (`scrapeSourceRefs`, `parseFrontmatterSources`, `parseArtifactMeta`, `collectSources`, `collectArchivedSources`, `collectModels`, `collectArtifacts`).
- `# NN Procedures` journal stays append-only (the only irreducible generated data). Hand-authored blocks pass through (e.g. `## NN External Watch Roots`, read by `skills/nn-trannsform/scripts/lib/external-scanner.js:108`).
- View fields in the cogNNitive bluepriNNt change from `reference` to `citation`. This fixes the dangling-reference false positive: `ModelRecords.derived_from` is typed `reference` (`iNNfo/specs/bluepriNNts/cogNNitive/spec_NN.md:120`) but the generator fills it with citations.

## Verified facts

- **All consumers sit on innfo-core:**
  - Editor `iNNfo/apps/innfo-editor/src/components/editor/FilePreviewModal.vue` "Linaje" tab: upstream from sidecar frontmatter, downstream via `stores/knowledgeStore.ts:217` `getSourceCitations` over `node.sources`.
  - Consoles: `iNNfo/packages/innfo-core/src/console/payload-builder.ts` -> `console/citations.ts` `resolveCitation` (origin/author from `## NN Agent Modification` block or `source_type: feedback`).
  - MCP `resolve_sources` (`iNNfo/packages/innfo-mcp/src/tools/resolve-sources.ts`).
  - NOTHING machine-reads the record's view sections except `lineage-check.js` (its own output). The editor graph drops `origin: 'source'` edges (`composables/useGraphData.ts:109`).
- innfo-core already states lineage is computed: `LEGACY_DERIVATION_KEY` message "write sources::; lineage is computed" (`iNNfo/packages/innfo-core/src/validator/workspaceSources.ts:160`). `#slug` is deprecated (`KU_DEPRECATED_HASH`). Cross-model qualified refs ARE validated (`validator/workspaceReferences.ts:397`), so `cogNNitive/spec_NN.md:245` is stale.
- `archive_path` / `superseded_by` are recomputed from `sources/archive/` (`provenance-knowledge.js:207-279`), not stored.
- No console emits lineage, so every console gets an empty `derived_from` in the record (`provenance-knowledge.js:437-512`). Consoles do embed `innfo-model.meta` with `modelId`, `modelVersion`, `sha256`.
- Artifact frontmatter `sources:` is only regex-scraped in JS, never validated by innfo-core.
- Two parallel PROV vocabularies: cogNNitive bluepriNNt (`derived_from_inputs`, `generated_by`, `produced_by` as `reference`) vs artifacts catalog bluepriNNt (`produced_by: string`, `sources: citation`). The artifacts catalog is generated by no script.

- `lineage-check.js` checks that re-verify its own freshly generated output. The `lineage-check.js:81` bug (strips only `#.*`, false "does not resolve" errors on canonical `@` and CSV citations) disappears by delegating citation checks to innfo-core `validateWorkspaceSources`.
- `impact-checker.js` duplicate heading-drift logic and its CSV-row / subunit gap -> delegate to innfo-core.

- `resolveUnitPath` accepts `models/` while `parseSourceRef` accepts `kNNowledge/` -> `kNNowledge/` only.
- Editor `utils/explorerClassify.ts:20`: `artifacts/` -> `export/` (used by `FileTreeNode.vue:125` and `WorkspaceExplorer.vue:228`), no fallback.
- Translate Spanish UI strings in `FilePreviewModal.vue` ("Archivo Original", "Linaje", "normalizado", "cita", etc.) to English.
- Docs: rewrite `docs/innfo/documentation/sources-citations-lineage.md` and `docs/skills/documentation/skills/citation-traceability.md` to the `@` grammar, the three rules, and record = view + journal; remove contradictions (OKF, canonical view, `sources/original/`). Fix the stale `sourceRef.ts:8-13` header and `cogNNitive/spec_NN.md:245`.

## Constraints

- The maintainer prefers deleting aliases and fallbacks (no backwards compatibility); sole user today.
- Published `_V_x-y-z_` spec files are write-once.
- bluepriNNt `spec_NN.md` files are edited in place WITH a `template_version` bump (CI guard) and registration in the editor's `SHIPPED_TEMPLATE_VERSIONS`; template changes require a new `templates-v*` tag and repin of `manifest/source.yaml` at release time. `manifest/source.yaml` `version:` means `spec_version`, not `template_version`.
- innfo-core relative imports need `.js` (NodeNext).
- Legacy code kept temporarily must carry a `legacy:<ns>/<id>` marker plus a `legacy-ledger.yaml` entry.
- Generated artifacts in English.
