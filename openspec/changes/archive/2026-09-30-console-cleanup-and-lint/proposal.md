# Proposal: Console cleanup and shell lint

Change 1 of 4 in the console chain: **cleanup-and-lint** -> design-tokens-and-ui-kit -> feedback-roundtrip -> review-ux.

## Why

Console shells drift silently. No gate compares a shell's declared `needs[]` with the DOM it ships or the pin it loads. Evidence from the code, checked 2026-09-30 (paths under `iNNfo/specs/bluepriNNts/`):

| # | Defect | Evidence |
|---|---|---|
| 1 | Feedback is declared but can never appear | `workspace/assets/model_console.html` declares `feedback-export` but has no `#innfo-export-open` / `#innfo-export-modal` / `#innfo-banner`. The bundle wires the button only when that anchor exists (`innfo-console.bundle.js:2851`). The 5 thin shells have the same gap. |
| 2 | Pins disagree | `model_console.html` pins `@innfo-console-v0.4.0`. The 5 thin shells load `@main`. `needs-registry.json` says `0.1.0`. `manifest/source.yaml` says `0.6.0`. |
| 3 | 5 orphan shells | `analysis`, `documentation`, `innovation`, `organization`, `projects` `*_console.html` differ only in title and `layout`. No procedure fills them. `layout` is read by nothing: it is absent from `console/*.js`, and `canonical-registry.ts` only mirrors the `assets:` id/path, generated by `scripts/generate-canonical-registry.mjs`. |
| 4 | Dead legacy asset | `business/assets/model_viewer.html` is kept "for one transition cycle" (`business/spec_NN.md:186`). No procedure targets it. |
| 5 | Export CLI drift | `scripts/export-console.mjs` rewrites only `artifact_shell`'s pin (`:398-403`). `markers` is `{}` at `:171` and `[]` at `:442`. |

## Scope

### In
- Delete `business/assets/model_viewer.html` and its `assets:` entry, with a blueprint version bump.
- Collapse the 5 thin shells onto the existing config-driven `console/artifact_shell.html`. Remove their `assets:` entries (or repoint them; see Q1). Regenerate `canonical-registry.ts` and the `innfo-mcp` bundle.
- Reduce `needs-registry.json` to capabilities only: `need -> required DOM anchors`, with no URLs and no pins.
- Add a deterministic guard, `scripts/lib/console-shell-guard.js` (modeled on `legacy-ledger-guard`), wired into `verify.js` and `check-integrity.js`. For every shell it checks:
  - `needs[]` ⊆ the registry;
  - the anchors each need requires exist;
  - the pin equals the manifest `console_assets` version.
- Add the 3 feedback anchors to `model_console.html` so defect 1 is fixed today.
- `export-console.mjs`: normalize the pin of every shell, and use one `markers` type.

### Out (left to later changes)
- Legacy `templates/console` path literals belong to the **nomenclature rename**. Exception: wherever a pin bump forces a path change, because the old path does not exist at the new tag.
- Design tokens and the UI kit go to change 2.
- Bundle-injected feedback UI and dropping the anchor rule go to change 3.
- The workspace hub's `templateProcedureMap` points at 6 procedures that do not exist (`workspace_hub.html:265-274`). That needs its own follow-up.
- Frozen test fixtures (`innfo-core/tests/**/fixtures`) stay unchanged.

## Capabilities

### New
- `console-shell-integrity`: needs/anchor/pin guard and a capability-only registry.

### Modified
- `console-architecture`: the "Level 2 Template Domain Consoles" requirement promises Funnel, Org Chart and Roadmap views that do not exist. Restate it as a single config-driven shell.
- `console-export-cli`: pin normalization covers every shell; one `markers` type.

## Risks

| Risk | L | Mitigation |
|---|---|---|
| A bundle or mcp consumer reads the removed shells | Med | Prove zero consumers with a test before deletion. Rebuild the mcp bundle. |
| Pin bump changes path literals that the rename also touches | Med | Coordinate. This change touches only lines the pin forces. |
| Guard goes red on shells not listed here | Med | Guard is TDD-first. Run it on the whole tree before wiring it in. |

## Release coupling
- A new `templates-v*` tag and a `manifest/source.yaml` repin, in the same batch, for the blueprint `spec_NN.md` edits (business, workspace, analysis, documentation, innovation, organization, projects).
- A new `innfo-console-v*` tag, because `export-console.mjs` is a `console_assets` entry.
- Refs come from `channel-refs.js` / `sync-versions.mjs` and are never hand-edited.
- The `innfo-mcp` release impact is an open question (Q3).

## Size (ask-on-risk)
About 1,100–1,300 changed lines, of which about 700 are whole-file deletions. **This exceeds the 400-line budget.** Suggested slices:
1. Guard, registry and anchors.
2. Shell collapse and legacy delete.
3. Export CLI and release.

## Rollback
Revert the slice commits on `dev`. The deleted files have no runtime reader. Tags are append-only, so the previous pins stay valid.

## Success Criteria
- [ ] The guard fails on the current `model_console.html` and passes after the fix.
- [ ] No `bluepriNNts/**/assets` shell declares a need without its anchors.
- [ ] Every shell pin matches the manifest.
- [ ] `model_viewer.html` and the 5 thin shells are gone, and `verify.js` is green.
