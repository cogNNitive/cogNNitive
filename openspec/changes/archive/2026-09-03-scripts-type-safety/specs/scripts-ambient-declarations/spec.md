# Scripts Ambient Declarations Specification

## Purpose

Governs the structure, coverage, and decoupling of `.d.ts` ambient and module declarations for repository tooling, tool manifests, skill definitions, and transformation pipeline contracts, enabling IDE auto-completion and static analysis without runtime impact.

## Requirements

### Requirement: Ambient Domain Type Declarations

Ambient declaration files (`.d.ts`) MUST define structural contracts, interfaces, and type aliases for script domain entities, including manifest definitions, skill structures, and transformation pipeline configurations. Ambient declarations MUST be discoverable by the TypeScript language server and `tsc` via root `tsconfig.json` configurations without requiring import statements in plain JavaScript files.

#### Scenario: JSDoc type references ambient interface
- GIVEN an ambient type definition `ToolManifest` defined in a `.d.ts` declaration file
- WHEN a JavaScript script references `@type {ToolManifest}` or `@param {ToolManifest}` in a JSDoc comment
- THEN `tsc --noEmit` MUST resolve the type definition successfully
- AND IDE tooling MUST provide accurate auto-completion for declared properties

#### Scenario: Unknown or invalid property access
- GIVEN an ambient declaration defining expected properties `{ name: string, version: string }`
- WHEN a script assigns or accesses a property `{ ver: "1.0.0" }` on that type
- THEN type verification MUST reject the invalid property
- AND the typechecker MUST issue a diagnostic specifying the undeclared property

### Requirement: Zero Runtime Footprint and Decoupled Typings

Declaration files MUST contain exclusively type-level information (interfaces, type aliases, declare statements). Declaration files MUST NOT introduce runtime side effects, require npm runtime dependencies, or require build-time transpilation.

#### Scenario: Clean runtime execution unaffected by declarations
- GIVEN JavaScript scripts typed against `.d.ts` declarations
- WHEN the scripts are executed directly with Node.js
- THEN Node.js MUST execute the files without loading or resolving `.d.ts` files
- AND zero runtime dependency overhead MUST be incurred

#### Scenario: Ambient definitions for untyped dynamic APIs
- GIVEN an ecosystem helper script consuming dynamic CLI arguments or un-typed Node APIs
- WHEN ambient declarations declare the shape of the dynamic context
- THEN `tsc --noEmit` MUST enforce property access against that declared shape
- AND any missing mandatory fields MUST trigger a static type error

### Requirement: Type Coherence Across Tooling Boundaries

Ambient declarations MUST maintain consistent naming and schema compatibility across tool boundaries (e.g., manifest generation in `scripts/manifest/` and skill ingestion in `actioNN/scripts/`).

#### Scenario: Schema conformance across tooling
- GIVEN a manifest payload generated by root scripts and consumed by actioNN scripts
- WHEN typed against shared ambient interfaces
- THEN both producer and consumer scripts MUST conform to identical structural types
- AND breaking schema changes in either producer or consumer MUST trigger typecheck failures
