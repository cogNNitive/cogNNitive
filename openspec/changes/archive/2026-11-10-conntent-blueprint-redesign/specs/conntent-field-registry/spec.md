# conntent-field-registry Delta Spec

Source decisions: D3, D5 (fields), D7 (field), C9 (Slice 2: Cascade). The full definition table (types, options, defaults, Concepts) of every field lives in `conntent-model` "Shared Field Definitions"; this capability fixes the scope classes, the generator rules, the source trace and the contract test.

## MODIFIED Requirements

### Requirement: The Registry Is Generated From Field Definitions

The skill MUST ship a generated registry (`lib/field-registry.generated.json`) built by one generator from the blueprint `spec_NN.md` Field Definitions and its frontmatter `validation.conditional_fields`, listing for every Field Definition its name, its scope `class` (`render`, `video`, `domain`, or `record` for non-cascading fields), the Concepts where it is settable, type, options, blueprint default, and whether it participates in the cascade. A Field Definition MAY declare a `scope::` attribute naming its class; no other consumer annotation MUST exist. A generated human-readable reference (`parameters.md`) MUST be produced from the same data. The registry MUST be regenerated by one command and MUST NOT be edited by hand.
(Previously: the registry listed no class, and a Field Definition could not declare one.)

#### Scenario: Registry equals the blueprint
- GIVEN the blueprint `spec_NN.md`
- WHEN the registry is regenerated
- THEN it lists exactly the Field Definitions of the blueprint with their class, Concepts, types, options and defaults

#### Scenario: Cascade parameters are flagged
- GIVEN the Field Definition `transition` with `scope:: render`
- WHEN the registry is read
- THEN `transition` is flagged as a cascade parameter of class `render` with its Concepts

#### Scenario: Record fields are not cascade parameters
- GIVEN the Field Definition `translation_of`
- WHEN the registry is read
- THEN its class is `record` and it is not flagged as a cascade parameter

### Requirement: Unknown And Retired Keys Are Rejected

Every document read by a run (episode, Series scope, domaiNN defaults, proposed changeset) MUST be rejected before any spend when it carries a `::` key that the registry does not define for that Concept (`unknown-key`) or that is retired (`retired-key`). The error MUST name the document, the Concept, the key and, for retired keys, the replacement if one exists; when the key exists with a class that does not allow the Concept, the error MUST name the class and the allowed Concepts. No alias, translation or silent ignore MUST exist.
(Previously: the error did not name the class.)

#### Scenario: Unknown key
- GIVEN a Scene declaring `scene_tts_model::`
- WHEN the pre-compile check runs
- THEN it fails with `unknown-key` naming the Scene and the key

#### Scenario: Retired key
- GIVEN a Video declaring `voice_tone::`, `scene_duration::`, `script_review::` or `published_url::`
- WHEN the check runs
- THEN it fails with `retired-key` and the run does not start
- AND for `script_review::` the error names the replacement `review_gates`

#### Scenario: Key valid on another Concept
- GIVEN a Scene declaring `budget::`, a `video` class field settable at Video Defaults, Series and Video
- WHEN the check runs
- THEN `unknown-key` names the Scene, states the class is `video` and lists the allowed Concepts

#### Scenario: Video-class field set on a Scene Kind or Preset
- GIVEN a Scene Kind or a Preset declaring `language::`
- WHEN the check runs
- THEN it fails with `unknown-key` (for a Preset, `preset-field`) naming the class `video`

## ADDED Requirements

### Requirement: Every Field Declares One Scope Class

Every cascade parameter MUST belong to exactly one scope class, declared once in its Field Definition and carried by the registry:

| Class | Levels where the field may be set (Concepts) |
|---|---|
| `render` | `Video Defaults` (domaiNN), `Series`, `Scene Kind`, `Preset`, `Video`, `Scene`, `Layer`, limited to those the Field Definition lists |
| `video` | `Video Defaults` (domaiNN), `Series`, `Video` |
| `domain` | `Video Defaults` (domaiNN) only |

A Field Definition MUST list only Concepts allowed by its class. The generator MUST fail with `scope-concept-mismatch` naming the field, its class and the offending Concept when a Field Definition lists a Concept the class does not allow, and MUST fail with `scope-missing` naming a cascade parameter that declares no class. The class of each cascade parameter MUST be:

| Class | Fields |
|---|---|
| `render` | `presets`, `voice`, `voice_model`, `voice_speed`, `voice_emotion`, `avatar`, `avatar_model`, `avatar_resolution`, `intro`, `image_model`, `image_size`, `background_audio`, `background_audio_volume`, `transition`, `frame`, `fit`, `components`, `sounds`, `captions`, `caption_model`, `character`, `pose`, `background` |
| `video` | `language`, `budget`, `output_formats`, `review_gates`, `thumbnail_formats`, `thumbnail_base`, `thumbnail_title`, `thumbnail_badge` |
| `domain` | `daily_budget` |

Fields that do not cascade (`tags`, `title`, `description`, `script`, `master`, `thumbnail`, `status`, `translation_of`, `kind`, `review`, and the Layer fields `type`, `placement`, `timing`, `style`, `source`, `asset`, `prompt`, `text`, `position`, `enter_animation`, `exit_animation`, `z_index`) MUST have class `record`.

<!-- shared with slice 3: the behaviour of `review_gates`, `captions` and `caption_model`, and the options of `status`, are specified by the Slice 3 capabilities; only their class and definition are fixed here. -->

#### Scenario: Class table is complete
- GIVEN the blueprint Field Definitions
- WHEN the generator runs
- THEN every field has a class and the classes equal the table above

#### Scenario: Concept outside the class
- GIVEN a Field Definition `language` with `scope:: video` listing `Scene`
- WHEN the generator runs
- THEN it fails with `scope-concept-mismatch` naming `language`, `video` and `Scene`

#### Scenario: Missing class
- GIVEN a cascade parameter Field Definition without `scope::`
- WHEN the generator runs
- THEN it fails with `scope-missing` naming the field

#### Scenario: Domain-only field
- GIVEN a Series declaring `daily_budget::`
- WHEN the check runs
- THEN it fails with `unknown-key` naming the class `domain`

### Requirement: Scene Kinds Accept Direct Fields

A `Scene Kind` MUST accept every `render` class field whose Field Definition lists `Scene Kind` (all `render` fields except `intro`), set directly on the kind. A kind's explicit fields MUST sit at the `kind` cascade level above the kind's own expanded `presets`, as specified by `conntent-presets` "Per-Level Additive Expansion Order". A `video` or `domain` class field on a Scene Kind MUST be rejected.

#### Scenario: Kind sets a field directly
- GIVEN a Scene Kind `Noticia` declaring `transition:: wipe` and `frame:: night`
- WHEN a scene of kind `Noticia` that sets neither resolves them
- THEN the values are `wipe` and `night` with source `kind`

#### Scenario: Kind field beats series
- GIVEN the Series `transition:: fade` and a Scene Kind `transition:: wipe`
- WHEN a scene of that kind resolves `transition`
- THEN the value is `wipe` with source `kind`

#### Scenario: Video-class field on a kind
- GIVEN a Scene Kind declaring `budget:: 2`
- WHEN the Series is checked
- THEN it fails with `unknown-key` naming the class `video`

### Requirement: Every Resolved Value Carries A Source Trace

The resolver MUST return, for every resolved value, a trace `{ value, source, document, overridden }` where `source` is one of `blueprint`, `domain`, `series`, `kind`, `video`, `scene`, `layer`, optionally suffixed `:preset:<Name>` or `:character:<name>`, `document` is the document that supplied it and `overridden` lists the sources that lost, nearest first. The compiler, the cost estimator, the persisted plan and the console payload MUST carry this trace and MUST NOT re-derive the level by other means.

#### Scenario: Plain level
- GIVEN `image_size` set at the Series only
- WHEN a scene resolves it
- THEN the trace has `source: "series"` and the Series document

#### Scenario: Preset and character suffixes
- GIVEN `voice` supplied by Preset `Lucas` at the Series and by Character `maria` at a Scene
- WHEN the scene resolves `voice`
- THEN the source is `scene:character:maria` and `overridden` includes `series:preset:Lucas`

#### Scenario: Estimator carries the trace
- GIVEN an estimate line for an image
- WHEN the line is inspected
- THEN it carries the trace of `image_model` and `image_size`

#### Scenario: Blueprint source
- GIVEN no level above the package sets `fit`
- WHEN a Layer resolves `fit`
- THEN the trace has `source: "blueprint"`

### Requirement: One Resolver Serves The Compiler And The Estimator

The scene compiler and the cost estimator MUST resolve every cascade parameter by calling the same resolver module, fed by the registry; neither MUST contain a per-field list of levels, a private cascade or its own default. The estimator MUST resolve `image_model`, `image_size` and `avatar_resolution` at every level the registry allows, including `Scene Kind`, `Preset`, `Scene`, `Layer` and the domaiNN, which fixes the truncated lists that left `avatar_resolution` Layer-only and `image_model`/`image_size` limited to series, domaiNN and blueprint.

#### Scenario: Image model set at a Scene
- GIVEN a Scene declaring `image_model:: m2` and the Series declaring `m1`
- WHEN the compiler and the estimator resolve the scene's image
- THEN both use `m2`

#### Scenario: Avatar resolution from the series
- GIVEN the Series declaring `avatar_resolution:: 720p` and an avatar Layer that sets none
- WHEN the compiler and the estimator resolve it
- THEN both report `720p` with source `series`

#### Scenario: No private level list
- GIVEN the scripts of the skill
- WHEN they are searched for literal arrays of level names or per-field level lists
- THEN none is found outside the registry and the resolver

### Requirement: A Contract Test Proves Every Field At Every Allowed Level

A contract test MUST derive its cases from the registry and, for every cascade parameter and every Concept the registry allows for it, build a fixture in which only that level sets the field to a unique sentinel value and assert that:

1. the compiler resolves the sentinel with the expected `source`;
2. the estimator resolves the same value with the same `source`;
3. when the field is set at that level and at the next outer level, the nearer wins.

The test MUST also assert, for every Concept the registry does not allow for the field, that the document is rejected with `unknown-key`. A new Field Definition MUST be covered with no test edit, and the test MUST fail when the compiler or the estimator disagrees on any (field, level) pair, naming the field, the level and the two values.

#### Scenario: Every field passes at every level
- GIVEN the generated registry
- WHEN the contract test runs
- THEN every (field, allowed level) pair resolves identically in the compiler and the estimator

#### Scenario: The three regression fields
- GIVEN the fields `image_model`, `image_size` and `avatar_resolution`
- WHEN the contract test runs
- THEN each is exercised at the domaiNN, Series, Scene Kind, Preset, Video, Scene and Layer levels where the registry allows it

#### Scenario: Disagreement is reported
- GIVEN an estimator that ignores `image_size` at the Scene level
- WHEN the contract test runs
- THEN it fails naming `image_size`, `scene` and the two values

#### Scenario: New field needs no test edit
- GIVEN a new Field Definition added to the blueprint and the registry regenerated
- WHEN the contract test runs
- THEN the new field is exercised without any change to the test

#### Scenario: Disallowed level is rejected
- GIVEN the field `language` and a fixture setting it on a Scene
- WHEN the contract test runs
- THEN the document is rejected with `unknown-key`
