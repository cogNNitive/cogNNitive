# Proposal: Harden publish-web

## Why

`scripts/publish-web.mjs` (shipped by the archived `2026-09-30-public-web-repository-split`)
is the only path from the private monorepo to the public `cogNNitive-web`. Investigation
confirmed four defects that break its own header contract:

| # | Defect | Evidence |
|---|---|---|
| 1 | Source guard is root-only | `assertNoSource` checks `FORBIDDEN_SOURCE` only when `!rel`; for `skills/` the "root" is skill folders, so `skills/nn-trannsform/node_modules/` (present on any dev machine, gitignored) is copied verbatim by a local run |
| 2 | `.nojekyll` is wiped | `PUBLISH_EXCLUDED` only hides it from `diffTrees`; on any non-identical site, `rmSync(docs)` + `cpSync` drops the public repo's `docs/.nojekyll` (private `docs/` has none) and `git add -- docs` stages the deletion |
| 3 | Token can leak | token is embedded in `cloneUrl`; a failed `execFileSync` throws `Command failed: git clone ... https://x-access-token:<token>@...` to stderr. Actions masking only covers the literal secret, and local runs have no masking |
| 4 | Temp clone survives failure | `process.exit(1)` in `assertNoSource`, reached from inside `try`, skips `finally`; the clone (with the token in `.git/config`) stays in `tmpdir` |

Also: the `publish-diff.js` header claims `CNAME` is excluded; it is not (harmless today, since private `docs/CNAME` exists).

## Guard semantics (decision for issue 1)

Nested manifests ARE legitimate: `skills/nn-trannsform/package.json` + `package-lock.json` ship so the skill can install its runtime deps. Therefore:

- **Forbidden at any depth**: `node_modules/`, `.env`, `.env.*`.
- **Forbidden at a surface root**: `src`, `packages`, `apps`, `package.json`, `package-lock.json`, `tsconfig.json` (unchanged).
- **Nested `package.json` / `package-lock.json`**: allowed only via an explicit allowlist (initially `skills/nn-trannsform/`).
- Guard runs on every surface BEFORE cloning; violations throw, never `process.exit`.

## What Changes

- Extract guard, copy and exclusion logic into a testable module under `scripts/lib/`; `publish-web.mjs` becomes a thin entrypoint with a single top-level exit.
- Public-repo-owned files (`.nojekyll`, `CNAME` if absent from the artifact) are preserved across the site replace, not just ignored by the diff.
- Credential never appears in argv, remote URLs, or error output (auth via env-scoped git config / askpass); all git errors pass through a redactor.
- Temp clone removed on every exit path.
- Tests first (strict TDD), in the Node test runner already used by `scripts/lib/publish-diff.test.js`.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `public-web-distribution`: adds requirements for deep source guarding with a manifest allowlist, preservation of public-repo-owned files, credential non-disclosure, and guaranteed temp cleanup.

## Impact

| Area | Impact |
|---|---|

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Stricter guard blocks the next real publish | Med | Dry-run against current `main` tree in tests; allowlist is explicit |
| Askpass/env auth behaves differently on the runner | Low | Keep `--dry-run` path; verify on first `main` publish |
| `.nojekyll` already deleted in the public repo by a prior publish | Med | Preservation rule re-creates/keeps it; check public repo state before apply |

## Rollback

Revert the change's commits on `dev`; `publish-web.mjs` returns to its current behavior. No data or public-history rewrite involved (publish stays append-only).

## Success Criteria

- [ ] A nested `node_modules/` or `.env` anywhere in a surface aborts publish before cloning.
- [ ] `skills/nn-trannsform/package.json` still publishes.
- [ ] A changed site publish leaves `docs/.nojekyll` intact in the clone.
- [ ] A forced git failure's output contains no token.
- [ ] No `publish-web-*` temp dir remains after any failure path.
- [ ] Non-goal held: no new publish features.
