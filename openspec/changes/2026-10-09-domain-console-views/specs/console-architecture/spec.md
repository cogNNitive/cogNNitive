# Delta for console-architecture

## MODIFIED Requirements

### Requirement: Level 2 Template Domain Consoles

Template consoles MUST contribute domain-specific views (e.g., Timeline in `metrics`, Funnel in `innovation`, Org Chart in `organization`, Roadmap in `projects`) by registering them in the domaiNN console runtime (see `console-view-registry`), composed from Level 1 primitives. Shells own layout only: they MUST take every color from the `--innfo-*` tokens and MUST NOT define their own color tokens. The prohibition on color values in shell `:root` blocks is enforced by `console-shell-guard`, not restated here.
(Previously: template consoles composed primitives into views conforming to layout slots and events, without a registration mechanism.)

#### Scenario: Template view composition
- GIVEN a bluepriNNt declaring a domain view
- WHEN the domaiNN console mounts
- THEN the view is registered, appears as a tab, and renders with shared Level 1 pills and cards

#### Scenario: Specialized layout uses tokens
- GIVEN the `timeline` or `procedure` view with `data-theme="dark"`
- WHEN rendered
- THEN its surfaces and text resolve from `--innfo-*` dark values

#### Scenario: Shells carry layout only
- GIVEN `artifact_shell.html`, `model_console.html` and every remaining console shell
- WHEN their style blocks are inspected
- THEN none declares a color custom property or a hex/`rgb(`/`hsl(` value in `:root`
- AND `console-shell-guard` fails if one does

### Requirement: Level 3 Model Custom Consoles

A domaiNN MUST have exactly one self-contained `domaiNN_console.html` generated by `scripts/export-console.mjs`, with one snapshot hash, one draft store, one shared edit modal and one changeset per export (D14). Specialized consoles MUST be views registered in that console runtime, not separate shells or iframes (editable views). The Workspace Hub MUST NOT exist.
(Previously: "Dedicated model consoles MUST register in the Workspace Hub to view compiled models.")

#### Scenario: One console per domaiNN
- GIVEN a domaiNN with several views
- WHEN exported
- THEN exactly one `domaiNN_console.html` is produced containing all of them as tabs

#### Scenario: No hub reference
- GIVEN the repository after this change
- WHEN searched for `workspace_hub`
- THEN there are zero hits outside the reference guard's allowlist (`test/no-workspace-hub-references.test.mjs`)

#### Scenario: No orphan domaiNN shell asset
- GIVEN the domaiNN bluepriNNt assets
- WHEN listed
- THEN no static `domaiNN_console.html` asset exists
