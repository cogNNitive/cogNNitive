# Lineage Drift Gate (Delta, new capability)

## Purpose

The persisted lineage record `*_cogNNitive_NN.md` is only trustworthy if its managed view sections equal what the core projection produces now. The gate fails when they differ. It compares managed sections only.

## ADDED Requirements

### Requirement: Managed sections must equal a fresh projection

The gate MUST compute a fresh projection with the innfo-core lineage projection and MUST compare, section by section, the on-disk text of `# NN Sources`, `# NN ModelRecords`, and `# NN Artifacts` with it. Any difference MUST be a failure.

#### Scenario: In-sync record passes
- GIVEN a record just regenerated by `--lineage`
- WHEN the gate runs
- THEN it passes

#### Scenario: Hand-edited managed section fails
- GIVEN a record where one line in `# NN Sources` was edited by hand
- WHEN the gate runs
- THEN it fails and names the section and the first differing element

#### Scenario: Workspace changed after the record
- GIVEN a new cognitivized file not yet in the record
- WHEN the gate runs
- THEN it fails reporting a missing element in `# NN Sources`

### Requirement: Only managed sections are compared

The gate MUST NOT compare the `# NN Procedures` journal, hand-authored blocks (including `## NN External Watch Roots`), or record frontmatter.

#### Scenario: Journal edit passes
- GIVEN a record whose `# NN Procedures` entry text was edited
- WHEN the gate runs
- THEN it passes

#### Scenario: Hand-authored block edit passes
- GIVEN an edited `## NN External Watch Roots` block
- WHEN the gate runs
- THEN it passes

### Requirement: Three run sites

The gate MUST run in (1) `nn-trannsform --lineage --check`, (2) `scripts/verify.js` over every non-frozen workspace it validates, and (3) the innfo-mcp `check_workspace` tool. A failure MUST yield a non-zero exit in (1) and (2) and an error-severity diagnostic in (3).

#### Scenario: CLI fails
- GIVEN a drifted record
- WHEN `nn-trannsform --lineage --check` runs
- THEN the exit code is non-zero

#### Scenario: verify fails
- GIVEN a drifted record in a validated workspace
- WHEN `node scripts/verify.js` runs
- THEN it exits non-zero naming the workspace

#### Scenario: MCP reports
- GIVEN a drifted record
- WHEN `check_workspace` runs
- THEN the response includes an error diagnostic for the record and the section

#### Scenario: All three agree on the clean case
- GIVEN an in-sync record
- WHEN the three sites run
- THEN all pass

### Requirement: The gate is read-only and tolerates absence

The gate MUST NOT modify any file; regeneration remains the job of `--lineage`. A workspace with no lineage record MUST NOT fail the gate; it MUST report that no record exists.

#### Scenario: No writes
- GIVEN a drifted record
- WHEN the gate runs
- THEN no file in the workspace changes

#### Scenario: No record
- GIVEN a workspace without `*_cogNNitive_NN.md`
- WHEN the gate runs
- THEN it passes with a "no record" notice

### Requirement: Comparison is deterministic across platforms

The comparison MUST be byte-based on section text as produced by the projection serializer. The record MUST be read without line-ending conversion, relying on the domaiNN `.gitattributes` (`* -text`).

#### Scenario: CRLF checkout
- GIVEN a record stored with LF and checked out on Windows with `* -text`
- WHEN the gate runs
- THEN it passes without a false difference
