# Native per-format rendering (retire the square master)

Objective: replace the 1920x1920 master + crop derivation with one semantic master (the episode script/model) rendered natively once per configured output format. Target: coNNtent blueprint V_0-25-0.
Branch: `session/native-format` (worktree `../cogNNitive-native-format`, from origin/main d0b63299). Lane: light (blueprint fields + engine; no MCP surface, no stored-data migration). Delivery: three PRs, each a release of the coNNtent blueprint (repo rule: more than one session = several changes). Test runner: `node --test` in `iNNfo/specs/bluepriNNts/coNNtent/skills/nn-conntent/test/`. Origin: copied from the coNNtent_NN domain tracker on 2026-11-17 (L16); this repo copy is the live tracker.
Status: SPECS FROZEN (T2, L12); cross-critique done (T1b, L15). S1-S9 are the contract. Next: T3.

## Specs

- **S1 — Semantic master, not a pixel master.** The single source of truth is the episode composition (script/model: scenes, layers, narration, timing). No pixel master file is rendered. Every output format is rendered natively from that composition. All formats share one timeline (same audio, scenes, durations); only layout differs per canvas.
  - User (L3): "Totalmente de acuerdo con la idea de master como fuente única fija"
  - User (L1): "sin realizar conversiones ni recortes innecesarios para que pasen por un formato cuadrado de 1920x1920"

- **S2 — Fit rules are blueprint defaults, overridable through the cascade.** Asset-to-canvas fit rules ship as defaults at blueprint level and resolve through the existing Universal Parameter Cascade (`layer > scene > video > kind > series > domain > blueprint`). Users may, at any level, replace a default with a dynamic HyperFrames treatment.
  - User (L3): "me parece bien que estas sean por defecto A nivel de blueprint y luego, a nivel de serie de dominio, serie, video o escena ya verá el usuario si se quiere dinamizar con HyperFrames o algo."
  - User (L1): "Los assets que tengan otras dimensiones: se podrían establecer reglas para ver cómo se encajan dentro de las dimensiones del canvas del video que se está generando. Por ejemplo esas reglas podrían ser blur en las partes que no se rellenan con el asset original o incluso completarlo mediante Hyperframes, posicionando de forma óptima los captions y los overlays."
  - Accepted proposal (L4, item 1 "Okay"): `fit::` becomes a keyed list resolved per key; the cascade includes the `layer` level because fit depends on the concrete asset.
  - Revised (L9, Q3): two keys only, `fit:: [native=cover, mismatch=blur]`, classified by asset aspect vs the allocated box within a documented tolerance. No `screenshot` key and no `role::` field: a screenshot is an ordinary image. A different presentation (e.g. `card`, zoom, a HyperFrames component) is an optional preset applied at layer or scene-kind level. Scalar `fit:: X` expands to both keys.
  - Frozen (L12): keyed values merge per key through the existing keyed cascade (union), so a lower level setting one key keeps the others. Built-in values: `cover | contain | blur | card`; every built-in has its own tested treatment. A HyperFrames component is a namespaced value `component:<name>`, resolved before any spend. Asset width/height are probed at compile time; unknown dimensions fail explicitly. The blur radius scales with the box size.

- **S3 — Output formats are a cascaded parameter.** Which formats an episode renders is configuration, not a constant. Blueprint default renders three formats (horizontal, vertical, square). Overridable through the cascade like any other blueprint parameter; e.g. a series may render horizontal only.
  - User (L3): "en vez de que siempre sea vertical y horizontal, debe ser una configuración, un parámetro de configuración como cualquier otro. Por defecto el blueprint debe generar los tres pero esto debe poder, en cascada, reescribirse como cualquier otro parámetro del blueprint. Por ejemplo puede haber series que solo generen renders en horizontal."
  - Accepted proposal (L4, item 2 "Okay"): resolves at domain → series → video only, NOT scene (a scene cannot be absent from one format without breaking the shared timeline).
  - Frozen (L12, Q1): blueprint default `output_formats:: [1920x1080, 1080x1920, 1080x1080]` (horizontal primary).
  - Square is a peer target, never the source of the others (L1: "incluso cuadradas, que podría ser un tercer formato a generar, pero no un master del que se derivan los vídeos verticales y horizontales").

- **S4 — The first format is the primary format.** The first entry of the resolved formats list is the primary format. AI-generated assets are generated in the primary format's aspect only; other formats consume that asset through the `fit` rules. Generating an extra aspect is an explicit per-asset opt-in, never the default.
  - Avatar (L10-L11, Q7): no exception. The avatar is generated once in the primary aspect from a crop-safe portrait (subject centered in the central 9:16 band). Other formats use centered `cover`. The engine warns when the per-format upscale factor exceeds a threshold; the remedy is the per-asset extra-aspect opt-in.
  - Frozen (L12, Q4): unless `image_size` is set explicitly, it derives from the primary aspect. When the model's catalog `sizes` lack that aspect, the engine picks the nearest supported size deterministically, discloses it in the estimate, and the other formats use `fit`. The image model catalog lists the real provider sizes.
  - User (L4): "Me parece bien que la regla sea la primera de la lista."
  - User (L3): "si solo se genera en 16:9 el render, no hace falta que se genere también el asset de IA en 9:16."

- **S5 — No migration.** Applies from V_0-25-0 onward. Existing episodes and series stay as they are (pinned to V_0-24-0). No official migration mechanism; users may migrate manually.
  - Resolved Q9 (L7): V_0-24-0 episodes are frozen archives; the engine keeps refusing mismatched pins (`episode.mjs:194-202`); no version dispatch.
  - User (L3): "Respecto a la migración no la vamos a hacer. Esto sería a partir de ahora y los vídeos antiguos y series antiguas se quedarían como están o ya las migraría el usuario a Docs, pero sin un mecanismo oficial."

- **S6 — Captions and overlays are positioned per canvas** using each format's safe areas (`@hyperframes/core/safe-areas`), not a central safe square of a master. (From L1: "posicionando de forma óptima los captions y los overlays"; assumption on the data source.)
  - Frozen (L7, L12, Q5): they stay HyperFrames sub-compositions. Their internal layout reads safe-area variables of the real canvas instead of the fixed 21.875% square inset; `placement:: inset` and authored animations follow the same per-canvas safe area. Registry blocks are queried before rewriting slots by hand. Per-aspect variants are opt-in only. QA measures overlays against the same per-canvas region.

- **S7 — Generate once, render N times** (L12, Q6). TTS, alignment, avatar and AI images are produced once into one immutable asset map before the format loop. Each format pass is cache-only and never calls a provider. Each format is compiled into its own HyperFrames project (`hyperframes/<WxH>/`). One preview animatic, in the primary aspect.

- **S8 — Outputs replace the master** (L8, L12, Q2, Q8). The `master` field is retired. The primary output is `<slug>_<output_formats[0]>.mp4`. `delivery.json`, its input fingerprint (over every format manifest), QA and the console describe all N outputs. `thumbnail_formats` stays independent; its first-frame fallback comes from the primary output.

- **S9 — Verification per format** (L12). Every emitted format project passes `hyperframes check`. Every output passes QA. A cross-format check asserts equal duration and timeline. An episode is delivered only when the whole configured set passes.

## Proposed fit rule model (draft, for review)

Classify each media layer by the relation between asset aspect and the box/canvas aspect:

| Key | When | Default |
|---|---|---|
| `native` | aspect matches within tolerance (OPEN Q5) | `cover` |
| `mismatch` | aspect differs beyond tolerance | `blur` (contain over blurred self-backdrop) |
| `screenshot` | layer marked as screenshot/UI capture | `card` (contain on designed frame background; never cropped) — new value |

Any key may name a HyperFrames component instead of a built-in value (S2 "dinamizar con HyperFrames").

### Ranked risks (implementation preconditions)

1. **R1 — Square inset hard-coded in components and QA.** Every slot sets `#root { inset: 21.875% }` and `data-width/height=1080` (`slots/title.html:5-22`, `slots/caption.html:6`, `slots/b-roll.html:6`). `qa.mjs:165-190` derives the overlay measuring band from `inset = 0.21875` on a 1920x1920 default. A native canvas without rewriting both gives crushed overlays and false QA `overlay-missing`. Blocks S6. (All three models.)
2. **R2 — Image generation cannot produce non-square sizes.** The catalog lists only `1024x1024`. `asset-synthesizer.mjs:347` hard-codes `aspect_ratio: '16:9'` for Replicate, `:655` sends `1024*1024`, and the offline SVG fallback is `1920x1920` (`:698`). Blocks S4. (Gemini; catalog part verified.)
3. **R3 — One `hyperframes/` project per episode.** `compile.mjs:843-847,962-967` writes a single `hyperframes/` and manifest. `render.mjs:90-111` shares one temporary output name and removes `hyperframes/assets` in copy mode (`:176-178`). `qa.mjs:544` reads `hyperframes/index.html`. A naive format loop clobbers itself. Fix: `hyperframes/<WxH>/` per format. (Codex, Gemini.)
4. **R4 — Synthesis re-entry per render.** See Q6. A loop of N renders must pass `synthesizeAssets:false` and consume one immutable asset map. (All three models; verified.)
5. **R5 — The `fit` emitter and type are not ready.** Only `blur` has a treatment branch; `contain` falls through to shared CSS that uses `cover` (`scene-project.mjs:98-119,155`). `fit` is a scalar `select` (`field-registry.generated.json:449-474`). A keyed form needs `resolveKeyed` union semantics (`cascade.mjs:73-86`); otherwise a scene setting `[mismatch=card]` wipes `native=cover`. The console only unions `components`/`sounds` (`console-view-conntent.data.mjs:114`).
6. **R6 — Domain overrides defeat the new defaults.** `video-defaults_NN.md:25,29,31` sets `image_size 1024x1024`, `fit cover`, square-first formats. Under S5 nothing rewrites them, so this domain must be edited deliberately when it moves to V_0-25-0.
7. **R7 — Single-output delivery contract.** `pipeline.mjs:759-784` fingerprints one manifest and writes `master`. Thumbnails take their base from `masterPath` (`:698-703`). Avatar warnings assume "a square master" (`avatar-jobs.mjs:108-110`).
8. **R8 — Blur radius is absolute.** "24px on a 1920 box" (`spec_NN.md:415`) must scale with the box size. (Claude.)

### What the specs miss (to add in T2)

- **Generate-once invariant:** TTS, alignment, avatar and AI images produce one immutable asset map; format passes are cache-only and never call providers.
- **Asset dimension probing:** classifying `native`/`mismatch` needs asset width/height at compile time. `layerMarkup` (`scene-project.mjs:76-121`) has no access to them today. Unknown dimensions must fail explicitly.
- **Layout contract per canvas:** safe rectangle, text limits, reserved caption and avatar regions; `placement:: inset` (`spec_NN.md:336-340`) is redefined against the per-canvas safe area.
- **Authored animations:** `type:: animation` mounts are not resized by `fit` (`scene-project.mjs:190-217`); they need responsive behavior or a fit wrapper.
- **Verification per format:** `hyperframes check` per emitted project (QA does not call it today), per-output QA, and a cross-format check that duration and timeline are equal.
- **Delivery/console:** where outputs live (retire `formats/`?), `inputFingerprint` over all N manifests, per-format QA in the console, and publishing only when the whole configured set passes.
- **Preview animatic:** one animatic in the primary aspect before the `preview` gate (`animatic.mjs:24-28`).

### Verdict on the draft fit-key model

**Keep `native`/`mismatch` with scalar broadcast.** Classify against the allocated box, not the canvas, using a documented tolerance (Gemini proposes 5%). Resolve with keyed union semantics in the existing cascade. Built-in values become `cover|contain|blur|card`. A HyperFrames component is a namespaced value (`component:<name>`), resolved before spend and given `{src, width, height, asset_width, asset_height}`. **Resolved (L9):** no `screenshot` key and no `role::`; `card` remains a built-in value usable from presets.
